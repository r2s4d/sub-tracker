# Тестирование пользовательского интерфейса

15 автоматизированных тест-кейсов, которые проходят сценарии сайта в настоящем
браузере: открывают страницы, заполняют формы, нажимают кнопки и проверяют,
что видит пользователь. Отчёт собирается в Allure.

## Чем это отличается от остальных тестов проекта

В проекте два набора тестов, они решают разные задачи.

| Набор | Чем запускается | Что проверяет |
|---|---|---|
| 278 тестов приложения (`subscriptions/tests/`, `accounts/`, `core/`) | `python manage.py test` | модели, расчёты, права доступа, ответы сервера. Браузера нет, JavaScript не выполняется |
| 15 UI-тестов (`uitests/`) | `pytest uitests` | то, что видит и делает человек в браузере: формы, сообщения об ошибках, переходы, работа JavaScript |

UI-тесты специально покрывают то, что первым набором проверить невозможно:
фильтры без перезагрузки страницы и раскрытие категории на диаграмме, то есть
код на JavaScript.

## Как устроено

- **Playwright** управляет браузером Chromium: открывает страницы, кликает, вводит текст.
- **pytest-django** поднимает настоящее приложение на локальном адресе и отдельную
  тестовую базу PostgreSQL. Браузер обращается к нему как обычный посетитель.
- **allure-pytest** записывает ход каждого теста по шагам и собирает отчёт.
- Данные каждый тест создаёт себе сам (файл `uitests/conftest.py`), поэтому тесты
  не зависят друг от друга и от порядка запуска.
- Если тест падает, в отчёт автоматически прикладывается скриншот страницы
  и её адрес.

## Запуск

Одной командой, вместе с отчётом:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run_ui_tests.ps1
```

Скрипт поднимает базу, прогоняет все 15 тестов, собирает отчёт Allure в папку
`allure-report` и открывает его в браузере. Окно с сервером отчёта остаётся
открытым, пока вы смотрите отчёт: закроете окно, сервер остановится.

Ключи скрипта:

| Ключ | Что делает |
|---|---|
| без ключей | прогон в фоне (окно браузера не появляется), сборка отчёта и открытие |
| `-Headed` | то же, но с видимым окном браузера: видно, что именно делает тест |
| `-OpenOnly` | не прогонять тесты, а открыть последний собранный отчёт |
| `-NoOpen` | прогнать тесты и собрать отчёт, но не открывать |

По умолчанию браузер работает в фоновом режиме (headless): окна нет, прогон идёт
быстрее. Видимый режим нужен, только чтобы показать тесты человеку.

Где что лежит: сырые данные прогона в `allure-results`, готовый отчёт
в `allure-report/index.html`. Обе папки в репозиторий не попадают.

Если нужно вручную:

```bash
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m playwright install chromium
docker compose up -d db

.venv\Scripts\python.exe -m pytest uitests --alluredir=allure-results
npx allure-commandline serve allure-results
```

Отдельный тест или группа:

```bash
pytest uitests/ui_auth.py                     # только авторизация
pytest uitests -k "негативный or wrong"       # по названию
pytest uitests --headed                       # с видимым окном браузера
```

Отчёту Allure нужна Java. Если её нет в системе, скрипт берёт ту, что поставляется
вместе с PyCharm, устанавливать отдельно ничего не нужно.

## Тест-кейсы

Восемь позитивных (система работает как задумано) и семь негативных
(система корректно отклоняет неправильные действия).

| Номер | Тип | Название | Что делает | Что проверяет |
|---|---|---|---|---|
| UI-01 | позитивный | Регистрация нового пользователя | Открывает форму регистрации, вводит имя, почту и пароль дважды, отправляет | Аккаунт создан, пользователь сразу авторизован и попал на обзор |
| UI-02 | негативный | Регистрация с занятой почтой | Пробует зарегистрироваться на почту существующего пользователя | Форма не отправлена, показана ошибка «Аккаунт с этой почтой уже есть», второй аккаунт не создан |
| UI-03 | позитивный | Вход с верным паролем | Вводит имя пользователя и правильный пароль | Открылся обзор с данными этого пользователя |
| UI-04 | негативный | Вход с неверным паролем | Вводит существующее имя и неправильный пароль | Остались на странице входа, показано сообщение об ошибке, обзор по-прежнему недоступен |
| UI-05 | негативный | Доступ после выхода | Входит, нажимает «Выйти», открывает обзор по прямому адресу | Сессия завершена: вместо обзора открывается форма входа |
| UI-06 | позитивный | Создание подписки | Заполняет форму: сервис, название тарифа, цена, тип оплаты, дата начала | Подписка сохранена, открылась её страница с введённой ценой, запись появилась в списке |
| UI-07 | негативный | Отрицательная цена | Вводит в поле цены минус 100 и сохраняет | Подписка не создана, под полем показана ошибка |
| UI-08 | негативный | Пробный период без даты окончания | Выбирает тип оплаты «Пробный период», не заполняет дату окончания и периодичность после него | Форма возвращается с ошибками у обоих обязательных полей, запись не сохраняется |
| UI-09 | позитивный | Отметка «оплачено» | Открывает подписку, указывает дату списания, нажимает «Отметить оплату» | Появилось сообщение об успехе, в истории платежей стало на запись больше |
| UI-10 | позитивный | Удаление подписки | Открывает подписку, нажимает удаление, подтверждает | Сначала показана страница подтверждения с предупреждением про историю платежей, после подтверждения подписка исчезла из списка |
| UI-11 | позитивный | Обзор расходов | Открывает обзор | Есть месячная сумма, кольцевая диаграмма действительно нарисована (Chart.js отработал), рядом текстовая легенда с категориями |
| UI-12 | позитивный | Фильтр по категории | Выбирает категорию в выпадающем списке на странице подписок | Список сузился до подписок этой категории, страница не перезагрузилась, адрес в строке браузера обновился |
| UI-13 | позитивный | Раскрытие категории на диаграмме | Нажимает на категорию в легенде, затем ещё раз | Список подписок категории раскрывается и сворачивается обратно |
| UI-14 | негативный | Чужая подписка по прямой ссылке | Под одним пользователем открывает адрес подписки другого | Ответ 404, данные чужой подписки не показаны. Именно 404, а не 403: посторонний не узнаёт, что запись существует |
| UI-15 | негативный | Закрытая страница без входа | Без входа открывает список подписок | Открывается форма входа, запрошенный адрес запоминается для возврата после входа |

## Соответствие файлов и кейсов

| Файл | Кейсы | Тема |
|---|---|---|
| `uitests/ui_auth.py` | UI-01 ... UI-05 | регистрация, вход, выход |
| `uitests/ui_subscriptions.py` | UI-06 ... UI-10 | создание, проверки формы, оплата, удаление |
| `uitests/ui_dashboard.py` | UI-11 ... UI-13 | обзор, фильтры, диаграмма |
| `uitests/ui_access.py` | UI-14, UI-15 | разграничение доступа |
| `uitests/conftest.py` | общая часть | данные для тестов, вход в систему, скриншоты при падении |

## Что показывает отчёт Allure

- список всех 15 кейсов с названиями на русском языке и пометкой, позитивный он или негативный;
- у каждого кейса описание «что делает» и «что проверяет», взятое прямо из кода теста;
- пошаговый ход выполнения: каждое действие отдельной строкой со временем;
- скриншоты: обзор и страница 404 прикладываются всегда, экран падения, если тест упал;
- разбивка по разделам сайта (авторизация, подписки, обзор, разграничение доступа)
  и по важности кейса.

Результаты одного прогона: 15 тестов, все пройдены, около 45 секунд.
